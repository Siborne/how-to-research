# 📝 观后感与想法记录

> 🧭 [首页](../../README.md) › [科研方向学习资料](README.md) › **观后感与想法记录**

读完论文、跑完代码之后，最重要的是把过程中的理解和想法沉淀下来。输出形式不一定是 PPT，一篇 Markdown 笔记、一份想法记录都可以。

## 可以记录哪些内容

1. **方向背景**：这个方向在解决什么科学问题？为什么重要？
2. **论文理解**：读了哪些论文，各自的核心思路是什么？（尽量用自己的话复述，不要照搬原文）
3. **代码实践**：跑通了什么、复现了哪些部分，遇到什么坑，怎么解决的。
4. **实验结果**：实验设置、结果，以及与论文结果的对比或差异。
5. **自己的想法**：哪里没看懂、哪里觉得可以改进、下一步想尝试什么。

## 建议的输出方式

- 首选写成 Markdown 笔记或想法记录，方便检索和后续迭代。
- 也可以整理成 PPT 分享给同学；如果做 PPT，不必加动画，导出 PDF 即可。
- 记录时保持「问题 + 理解 + 证据」的结构，比单纯罗列论文更有效。

## 小提示

- 复现失败也算收获：重点记录「定位问题的过程」和「可能的原因」。
- 每读完一篇论文，尝试用三句话讲清楚：解决了什么问题、怎么解决、有什么局限。
- 定期回头补充或修正之前的笔记，让想法持续沉淀。
